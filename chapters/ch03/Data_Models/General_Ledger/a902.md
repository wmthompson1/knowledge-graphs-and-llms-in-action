## KB0738580 ##

What triggers costing utilities to change the posting candidate?

Article Information
_____________________________________________________________________________________________


Description : What triggers costing utilities to change the posting candidate?

Resolution :
The POSTING_CANDIDATE flag exists in the following tables

WORK_ORDER
PURCHASE_ORDER
CUSTOMER_ORDER
INVENTORY_TRANS (used for adjustments only)
LABOR_TICKET (used for indirect labor only)

In a Projects database
PAYABLE
GJ

When a transaction is entered or updated against one of the above transaction types, the POSTING_CANDIDATE is set to Y.

For example, if material is issued to a work order, the POSTING_CANDIDATE in the WORK_ORDER table is set to Y for the work order.  If a Work Order is Closed or Canceled and a transaction is performed against it, the posting candidate will be turned on so that the work order total cost is reevaluated.  Once the transaction has been fully evaluated and journalized, the POSTING_CANDIDATE is set to N.

There are some other ways the posting candidate may be turned on:

1.  Costing Tools:  Running Recalculate Distributions or Force FIFO
2.  Entering a voucher linked to a receiver that changes the receiver value.  If the Source of Raw Material = A/P Invoice, this will change the Inventory/receiver value, which would then flush through to any transaction(s) connected to the receiver.
3.  VMFIXWRK.exe or VMFIXWOQ
4.  An outside process
5.  In Part Maintenance, Reset Material Requirement Costs or in Shop Resource Maintenance, Reset Operation Costs when updating work orders. 
6.  Upgrades.  It is recommended that a full costing and post be completed prior to upgrading. 

If a posting candidate remains set to Y after running a full costing and posting the journals, there could be activity for the transaction in a future period.  Costing will not turn off the flag until the transaction has been fully journalized.
