Resolution :
When Costing Tools displays exceptions, the value in one table does not equal the value in another table.  There are two columns displayed:  'Total Transactions' and 'Total Posted'.  Additionally, if 'Detail' is checked, there is a third column, 'Total Trans Detail'.

'Total Transactions':  The total of all transactions as of the current date.
'Total Trans Detail' and 'Total Posted':  The total of all transactions as of the 'Posting Date' entered which is the date journals have been prepared for.  Therefore, if there are transactions dated after the 'Posting Date', exceptions may be displayed because the future dated transactions will be included in the 'Total Transactions' column but not 'Total Trans Detail' or 'Total Posted'.

If the POSTING_CANDIDATE on a transaction = Y, the transaction will not display as an exception as it has not been processed through Costing Utilities.  The transaction WILL show on the Journal Preparation Analysis report.

To clear an exception
If Costing Tools displays an exception or if it is perceived there is an issue with a transaction:

'Cost to Check':  Select the appropriate type
Starting and Ending:  The specific transaction can be entered if known
'Posting Date':  Date journals are currently being prepared for (To verify, check the Inventory Balance or WIP Balance Report.  If there is data listed for the period, journals have been prepared). 
'Options':  Check 'Exceptions Only'
Run

If any rows appear, go to Edit > Select All
Select the 'Set Posting Candidate' icon
Save 
Select the 'Journal Preparation' icon

If the exception clears, a journal was created.  To post, go to Ledger > Post Manufacturing Journals.

WIP/Finished Goods
If these steps do not clear a WIP or Finished Goods exception, in TEST, run VMFIXWRK.exe against the work order.  

VMFIXWRK is an executable within the VISUAL executable library that recalculates the WORK_ORDER table cost fields.  VMFIXWRK recalculates requirement costs from issues, operation costs from labor tickets, and operation costs for services.  The cost information written to the WORK_ORDER table is summarized from the OPERATION and REQUIREMENT tables. If any changes are made, it will change the posting candidate to Y so the corrected costs flow through.  Run a full costing in order to see the change.

It is recommended VMFIXWRK be run in TEST prior to running in live to review the results, especially the financial impact.

To run VMFIXWRK.EXE:

1.  No users can be logged in
2.  Locate the executable within the VISUAL directory
3.  Double click to log in
4.  Enter a specific work order, eng master, or quote master to recalculate.  Check the bottom 3 check boxes and select 'Go'.

Shipment
If these steps do not clear a Shipment exception, refer to related KB0731193.

Note :
If journals are prepared out of order, Costing Tools will display an exception as the values used from the _DETAIL tables are based on the last DIST_NO.

Additional information re:  DIST_NO
When journals are prepared in Costing Utilities, the _DETAIL and _DIST tables are built.  If the transaction has had a distribution previously, any difference between DIST_NOs is journalized.

Example using a work order receipt
Work order value = 100.00; work order is received
DIST_NO 1 = 100.00

Additional material is issued to the work order, value = 25.00
DIST_NO 2 = 125.00
Journal is created for 25.00

Additional material is issued to the work order, value = 10.00
DIST_NO 3 = 135.00
Journal is created for 10.00

DIST_NOs are generated by Costing sequentially.  If a DIST_NO is missing, in the above example, there is a DIST_NO = 1 and DIST_NO = 3, DIST_NO = 2 was deleted from the table directly.
