Before beginning, ensure all transactions are entered and posted.

Print the Inventory Balance Report:  Ledger > Post Manufacturing Journals > Reports > Inventory Balances.  This should match to the balance in the Accounting Window for the Inventory account. If it does not, follow these steps:

1. In Ledger > Accounting Window, pull up the Inventory account. Drill into the period and ensure the only batch types are from Costing Utilities:

ADJ: Inventory Adjustments
PUR: Purchasing
SLS: Sales
WIP: Work in Process
FG: Finished Goods

If there are other batch types, these should be reversed using a General Journal Entry.  Refer to related KB0732063 for additional details on obtaining a GJ total.

2. Verify that there are no 0.00 batches.  These batches may not have posted correctly due to changing screens or other disturbances while posting and would create a batch for zero dollars.  To find $0 batches, go to Ledger > General Journal Entry > Edit > View Batch Information and browse batch ID's by posting date.  If the amount is $0.00, pull them into the window.  If there are no details to the batch, the batch needs to be deleted and reposted. Reference related KB1015071. 

3. Any transactions that are not posted because of an error in the date can be found by running the following SQL statements:

SELECT * FROM ADJUSTMENT_DIST WHERE POSTING_STATUS = 'U'

SELECT * FROM PURCHASE_DIST where POSTING_STATUS = 'U'

SELECT * FROM RECEIVABLE_DIST where POSTING_STATUS = 'U'

SELECT * FROM SHIPMENT_DIST where POSTING_STATUS = 'U'

SELECT * FROM WIP_ISSUE_DIST where POSTING_STATUS = 'U'

SELECT * FROM WIP_RECEIPT_DIST where POSTING_STATUS = 'U'

Any future dated transaction would not cause a problem. Transactions with an invalid posting date would need to be examined.

4.  In a static environment, compare each part on the Inventory Valuation Report with the Inventory Balance Report.  For any discrepancies, run Recalculate Distributions.

Recalculate Distributions verifies OUT transaction(s) connected to IN transaction(s) are valued properly.
Recalculate Distributions should be run in a fully costed test database to validate the results.

Admin > Costing Tools > Options > Recalculate Distributions
'Process Transactions on or After':  Enter a date a few days prior to the transaction(s) that need to be corrected 
'Starting Part ID' and 'Ending Part ID':  Enter the Part ID that requires correction
'Recalculate Distributions' = check
'Start'

Run a full costing and post to validate the financial impact.

5. If parts remain out of balance after running Recalculate Distributions, contact support and reference KB1543275.  Please provide the following information:

Inventory Valuation Report for the part

Inventory Balance Report, in detail, for the part

FIFO/Average Costing Analysis Report for the part

The results of the following statements – replace the variable with the part ID that does not reconcile.  

If running in Admin > Query Tool, select 'No Auto Joining':

SELECT * FROM INVENTORY_TRANS WHERE PART_ID = '<ENTER PART ID HERE>' AND COSTED_QTY < > QTY

SELECT * FROM INV_TRANS_DIST WHERE IN_TRANS_ID IN 
(SELECT TRANSACTION_ID FROM INVENTORY_TRANS WHERE PART_ID = '<ENTER PART ID HERE>' AND COSTED_QTY < > QTY)

SELECT * FROM INV_TRANS_DIST WHERE OUT_TRANS_ID IN 
(SELECT TRANSACTION_ID FROM INVENTORY_TRANS WHERE PART_ID = '<ENTER PART ID HERE>' AND COSTED_QTY < > QTY)

SELECT * FROM INV_RECEIPT_DIST WHERE INV_TRANS_ID IN (SELECT TRANSACTION_ID FROM INVENTORY_TRANS WHERE
PART_ID = '<ENTER PART ID HERE>' AND COSTED_QTY < > QTY)

SELECT * FROM INV_TRANS_AVE WHERE TRANSACTION_ID IN (SELECT TRANSACTION_ID FROM INVENTORY_TRANS WHERE
PART_ID = '<ENTER PART ID HERE>' AND COSTED_QTY < > QTY)
