
# Entry Shape Task Handler
A concise “task brief + output format” template for repeated SQL lineage investigations.
The delta files may be exluded from the lineage investigation, but the lineage investigation 
should be repeated for each of the SQL files in this folder.

The difference between the two shapes is the focus. The actual change depends on accxeptance and may be in A or B.

The word shape is used to denote the ddl used to describe the result.

## Prompt
Two queries are presented.
Investigate the result-set shape for the target SQL in this folder. Use repository evidence as the source of truth, trace the final output schema, identify any implicit conversion or type drift, explain the root cause, produce the corrected DDL and materialization logic, and validate union compatibility against the peer query. Focus on differences between the two shapes, especially Sortation and any data-type-sensitive fields. Do not assume schema definitions. Use the repository’s lineage artifacts and metadata to support every conclusion. Return the final report in the standard output contract.

## Acceptance criteria:

The result set definition for Query B is supported by repository evidence.
The difference between the two shapes is the focus.
The runtime conversion error (due to difference in shape) is explained and eliminated.
A UNION statement contract may be used to trigger any shape difference errors.
The Query A / Query B UNION contract is explicit and deterministic, used to ensure shape is consistent.
The final answer is ready for implementation or review by a SQL engineering team.
