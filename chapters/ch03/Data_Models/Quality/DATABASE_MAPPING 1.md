# NCM Database Field Mapping

**Sandbox DB:** `SANDBOX_NCM` on `CRUNCH2018.skillsinc.local`
**Production DB:** `NCM` on `SQL-Visual-2.skillsinc.local`
**Primary table:** `dbo.NONCONFORMANCE` (target schema — identical in both environments)
**Last Updated:** 2026-07-08

---

## Core Rules

### Environment routing

- Client requests must include `x-db-env`.
- API routes resolve it with `getDbEnvFromHeader(request)`.
- Queries run against sandbox or production based on that header.
- Both environments use the **target schema** table names from `lib/dbSchemaContract.ts` (`getDbObjects()` / `getLookupObjects()` always return `TARGET_*`).

### Payload keys vs database columns

The client form still sends **legacy-style payload keys** (e.g. `MADE_BY_EMP_REC_ID`, `USER_DEFINED_1`, `SK_AS_IS`). The API route translates them to target-schema columns through `targetFieldMap` in `app/api/ncm/[id]/route.ts`. The GET query aliases target columns back to the legacy names the form expects. See the alias table at the bottom.

### Natural IDs, not record IDs

Unlike the legacy `VQ_*` layout, the target schema stores **natural identifiers** directly:

- Part Number → `PART_ID` (part number text)
- Work Order → decomposed into `BASE_ID` / `LOT_ID` / `SPLIT_ID` / `SUB_ID`
- Operation → `OPERATION_ID`
- Employee fields → `*_EMPLOYEE_ID` columns holding the badge ID, joined to `EMPLOYEE_LOOKUP.EMPLOYEE_ID` for display names
- Supplier → `REPORTED_BY_SUPPLIER_ID`

## GET Joins Used by `GET /api/ncm/[id]`

```sql
FROM [dbo].[NONCONFORMANCE] NCM
LEFT OUTER JOIN [dbo].[DISPOSITION_TYPE] DT
  ON DT.[DISPOSITION_TYPE_CODE] = NCM.[DISPOSITION_TYPE_CODE]
LEFT OUTER JOIN [dbo].[EMPLOYEE_LOOKUP] MADE_EE
  ON MADE_EE.[EMPLOYEE_ID] = NCM.[MADE_BY_EMPLOYEE_ID]
LEFT OUTER JOIN [dbo].[EMPLOYEE_LOOKUP] ASSGN_EE
  ON ASSGN_EE.[EMPLOYEE_ID] = NCM.[ASSIGNED_TO_EMPLOYEE_ID]
LEFT OUTER JOIN [dbo].[EMPLOYEE_LOOKUP] DISP_EE
  ON DISP_EE.[EMPLOYEE_ID] = NCM.[DISPOSITION_BY_EMPLOYEE_ID]
LEFT OUTER JOIN [dbo].[EMPLOYEE_LOOKUP] DISP_ASSG
  ON DISP_ASSG.[EMPLOYEE_ID] = NCM.[DISPOSITION_ASSIGNED_TO_EMPLOYEE_ID]
LEFT OUTER JOIN [dbo].[EMPLOYEE_LOOKUP] VERIFY_BY_EE
  ON VERIFY_BY_EE.[EMPLOYEE_ID] = NCM.[VERIFIED_BY_EMPLOYEE_ID]
WHERE NCM.[NCM_NUMBER] = @ncm_id
```

## Lookup and Resolution Notes

### Employee ID resolution

- The update route accepts either a badge `EMPLOYEE_ID` or an internal `RECORD_ID` and normalizes to the badge ID stored in `*_EMPLOYEE_ID` columns.
- Display names come from the `EMPLOYEE_LOOKUP` joins; falls back to `/api/employee/[id]` (Visual `LiveSupplemental.dbo.ADP_EMP` first).

### Part, work-order, and operation resolution

- Part validation checks Visual `LIVE.dbo.PART` and the `PART_LOOKUP` table.
- Work order validation uses `WORK_ORDER_LOOKUP` / Visual `LIVE.dbo.WORK_ORDER`.
- Operation validation uses the selected work order and Visual `LIVE.dbo.OPERATION` to derive `RESOURCE_ID`.

## Not Stored Directly

These values are display-only or derived:

- All employee name fields
- Disposition type description
- `time`, which is derived from `NCM_DATE`
