KB0742317

## Costing Utilities is looping, continuously running through the top 2 options.

Article Information
________________________________________________________________________________________________________________


Description :

Costing Utilities is looping, continuously running through the top 2 options.
The VMAPLUTL_SITE ID.LOG file indicates that the same number of transactions are continuously being looked at each cycle repeatedly.

 

 


Resolution :
There are 4 possible causes/resolutions to this issue:

1.  Rounding issue:  A rounding issue may exist where costing is continuously rounding up a penny and down a penny because manufacturing can go out to 6 decimal places but finance goes to 2 decimals.

To resolve:  The rounding cannot be resolved so the cycles would be used to have Costing Utilities process a set number of cycles.  Cycles are in the Setup icon of Costing Utilities.  To determine the correct number of cycles, go to Eng/Mfg > Bill of Material Report.   Type = Eng Master.  Select the largest Part ID manufactured.  Uncheck the bottom 3 boxes.  This will generate a report showing the number of levels. The cycles specified should be 2 more than the max number of levels.
  
2.  Issue return dated before the issue:  Review the Costing Log to identify this scenario.  The Costing Log (VMAPLUTL_SITEID.LOG is located in the directory with the VISUAL executables.  The error would be:  "No Issue trans prior to return ###### Failed on Part ######" 

To correct this condition, contact support.

3.  Zero dollar returns:  In VISUAL versions 8.0 and higher, RET_COST_ZERO was added to the INVENTORY_TRANS table to indicate the value of a return should be 0.  If this field is not updated properly when the database is upgraded, it can cause costing to loop.  To identify, run the following statement.
per KB0742317  If rows are returned, contact support. 
```sql
SELECT * FROM INVENTORY_TRANS WHERE TYPE = 'I' AND CLASS = 'I' AND PART_ID IS NOT NULL AND ACT_MATERIAL_COST =0 AND  ACT_LABOR_COST = 0 AND ACT_BURDEN_COST = 0 AND ACT_SERVICE_COST = 0 AND RET_COST_ZERO IS NULL 
```

4.  Identify transactions that are being reviewed.  Follow the steps in attached KB0731809 to potentially identify the transaction(s) that are causing the issue.
