KB0731809

## Costing Utilities continues to update transactions after running to completion.

Article Information
________________________________________________________________________________________________________________


Description :

When running Costing Utilities, the window appears indicating the number of transactions processed.  If Costing Utilities is then run again, transactions still continue to be processed.



Resolution :
If there are future dated transactions, costing will continue to have updates.  This will not cause any problems.

If there are no future dated transactions, there is a transaction(s) causing Costing Utilities to continuously look at the transaction(s) without being able to finish costing the transaction(s).

To identify the transaction(s):

1. Ledger > Costing Utilities > Setup.  ‘__ cycles are performed’ should be blank.  If costing loops, then set the cycles to a number higher than the largest bill of materials.  Run a full costing and post.

2. Set   ‘__ cycles are performed’ = 1.  Run the top 2 options of Costing Utilities.

Run the following script to identify the workorder(s) that are not being fully costed:
SELECT * FROM WORK_ORDER WHERE POSTING_CANDIDATE = 'Y' AND TYPE = 'W' AND SUB_ID = '0';

3.  Review any work order(s) on the Work Order Master Cost Report/Comparative Totals, selecting 'Comparative totals with breakdown'.   Verify the WIP and Finished Goods postings match.  If they do not, run VMFIXWRK.EXE. 

VMFIXWRK is an executable within the VISUAL executable library that recalculates the WORK_ORDER table cost fields.  VMFIXWRK recalculates requirement costs from issues, operation costs from labor tickets, and operation costs for services.  The cost information written to the WORK_ORDER table is summarized from the OPERATION and REQUIREMENT tables. If any changes are made, it will change the posting candidate to Y so the corrected costs flow through.  Run a full costing in order to see the change.

It is recommended VMFIXWRK be run in TEST prior to running in live to review the results, especially the financial impact.

To run VMFIXWRK.EXE:

1.  No users can be logged in
2.  Locate the executable within the VISUAL directory
3.  Double click to log in
4.  Enter a specific work order, eng master, or quote master to recalculate.  Check the bottom 3 check boxes and select 'Go'.

4.  Check to see if the work orders are exceptions. If they are, force them through Costing Tools.

Admin > Costing Tools
'Cost to Check' = ‘WIP’
'Starting Base ID' and 'Ending Base ID' = Workorder ID 
'Posting Date' = Date journals are currently being prepared for (To verify, check the Inventory Balance or WIP Balance Report.  If there is data listed for the period, journals have been prepared). 
'Exceptions Only' = Uncheck
Run
When the row appears, highlight the row
Select the 'Set Posting Candidate' icon
Save

5.  Issue Returns valued at 0.00 could cause this issue.  Refer to related KB0742317.
